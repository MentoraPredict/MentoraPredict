# MentoraPredict Desktop Application

## Overview

The MentoraPredict desktop application is a Windows desktop distribution of the existing MentoraPredict web application. It uses Electron to package the React/Vite frontend inside a native desktop shell and electron-builder to generate a Windows installer.

The desktop application does not implement a separate frontend. It reuses the same web application from `apps/web`, builds it as static assets, and bundles those assets inside the Electron package.

## Technologies Used

- Electron: native desktop shell for Windows.
- React: user interface layer reused from the web application.
- Vite: frontend build tool.
- TypeScript: typed source code for the desktop main process and web app.
- pnpm workspaces: monorepo dependency and script management.
- electron-builder: Windows packaging and installer generation.
- NSIS: installer technology used by electron-builder to create `Setup.exe`.
- Kong: API Gateway used by the desktop app to reach backend services.
- Docker: local backend runtime for development/testing.

## How It Works

In development mode, Electron opens the Vite dev server:

```text
http://localhost:5173
```

In packaged mode, Electron loads the compiled web assets bundled in:

```text
process.resourcesPath/web
```

The application uses a custom Electron protocol:

```text
mentorapredict://app
```

This avoids loading the Vite build directly with `file://`, which can block JavaScript and CSS modules. The custom protocol serves files from the bundled `web` directory.

## Backend Connection

The API base URL is compiled into the frontend during the Vite build. Each desktop build mode uses a different environment file:

```text
package:local -> apps/web/.env.desktop.local
package:qa    -> apps/web/.env.desktop.qa
package:prod  -> apps/web/.env.desktop.prod
```

For local testing:

```env
VITE_API_BASE_URL=http://127.0.0.1:8000/api
```

For QA:

```env
VITE_API_BASE_URL=https://mentorapredictqa.programacionwebuce.net/api
```

For production:

```env
VITE_API_BASE_URL=https://mentorapredictprod.programacionwebuce.net/api
```

## CORS Requirement

Because the packaged desktop app runs from:

```text
mentorapredict://app
```

Kong must allow that origin in CORS. The local Kong configuration includes this origin in:

```text
infra/kong/kong-template.yml
```

and the local service environment includes it in:

```text
infra/.env
```

If `mentorapredict://app` is not allowed, login and registration can fail in the desktop app even if the web application works correctly.

## Development Commands

Run the desktop app in development mode:

```powershell
pnpm.cmd --filter @mentorapredict/desktop dev
```

Build only the Electron main process:

```powershell
pnpm.cmd --filter @mentorapredict/desktop build
```

Clean generated desktop artifacts:

```powershell
pnpm.cmd --filter @mentorapredict/desktop clean
```

Generate a local installer:

```powershell
pnpm.cmd --filter @mentorapredict/desktop package:local
```

Generate a QA installer:

```powershell
pnpm.cmd --filter @mentorapredict/desktop package:qa
```

Generate a production installer:

```powershell
pnpm.cmd --filter @mentorapredict/desktop package:prod
```

## Installer Output

The installer is generated in:

```text
apps/desktop/release/
```

The expected installer file is:

```text
MentoraPredict_Setup_1.0.0_x64.exe
```

The `release` directory also contains `win-unpacked`, which is the unpacked application folder generated by electron-builder. The installer is the file intended for delivery to users.

## Update Workflow

For frontend-only changes, rebuild the installer:

```powershell
pnpm.cmd --filter @mentorapredict/desktop package:local
```

For a clean rebuild:

```powershell
pnpm.cmd --filter @mentorapredict/desktop clean
pnpm.cmd --filter @mentorapredict/desktop package:local
```

When testing packaging or backend configuration changes, uninstalling the previous desktop installation before installing the new one is recommended.

## Notes

- The desktop application is currently unsigned. Windows may show an "unknown publisher" warning.
- The installer is generated with NSIS, not MSI.
- `productName` controls the visible application name.
- The package name `@mentorapredict/desktop` is kept as the internal pnpm workspace package name.
